## Rolladice Work — persistent task and review queue

Use the owner's connected **Rolladice Work** project **Creative Flow — Universal Workbench** (code `CFLOW`, project UUID `72b41a4b-6d38-4cb8-a98d-5f594f4055d4`) to coordinate future Codex work. The Git repository is the source of code, decisions and evidence; Rolladice Work is the persistent task assignment, dependency, discussion and owner-review record. These are complementary, not competing sources of implementation truth.

- At session start, read `AGENTS.md`, `STATE.md`, the accepted scope and `rolladice_work_read_workspace({projectId:"72b41a4b-6d38-4cb8-a98d-5f594f4055d4",view:"summary"})`. **Do not read the full multi-project workspace** for routine planning. Use `rolladice_work_get_task({taskId,view:"brief"})` or `rolladice_work_get_handoff({taskId})` for the selected ticket; use `get_task` with `view:"discussion"` only when needed. Display references such as `CFLOW-001` are human labels; mutations use stable task UUIDs.
- Select a ticket only when its dependencies, pinned standards and the owner's stage authorization permit starting. A TODO ticket does not itself authorize a new stage, merge, deployment, deletion, paid provider call or scope expansion. Do not restart completed work merely because it predates a ticket. Clarify ambiguity in the ticket's discussion; if permissions or the Rolladice connector are unavailable, report the blocker and continue only with separately authorized local work.
- Before execution, use the ticket handoff and claim an AI worker run with `rolladice_work_update_work(action:"run_start")`, including the stable task UUID and worker identity. Keep the run alive with `run_update` heartbeats every few minutes while working; record meaningful progress, blockers and the final exact PR/commit and demonstration with `run_update` and/or `task_update`. For a genuine blocker, post a `task_comment` and use `task_status` accordingly. Claiming a run records work; it does not automatically launch Codex.
- For **every** Rolladice mutation, first read the current global workspace revision, pass a unique `operationId` (reuse it only when retrying the same operation), and reread/reconcile on revision conflict. Keep task comments concise; link GitHub artifacts rather than pasting huge logs or secrets. On finished AI work, leave the ticket in **Review** with evidence and questions, then stop. **Only Radzi accepts/marks Done via the owner workflow**; do not self-accept or remove reviewers.
